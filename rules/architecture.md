# 架构与代码组织

> 读取时机：引入抽象、通用封装或依赖，改变模块职责、依赖方向、公共契约、状态归属或跨层边界时。

## 职责与权威入口

- 先定位真实调用链、数据源和消费者，再决定修改位置；优先沿用项目已有结构。
- Python 节点与处理逻辑按图片、媒体、视频、音频、文本职责分包，共享资源服务在 `library/`；根 `__init__.py` 统一显式注册。新增实现放入对应分类，调整目录时同步相对导入、测试入口及上下文，不按目录扫描动态注册，也不新增无实际消费者的旧模块兼容壳。
- 同一业务规则、schema、状态和能力定义只维护一个权威来源，其他入口通过委托或派生复用。
- 展示负责呈现和输入，核心规则不依赖具体 UI；外部存储、网络和供应商细节放在明确边界。只在实际复杂度需要时引入应用层、领域层、adapter 等结构，不机械建立四层目录。
- 临时 UI 状态留在局部；共享与持久化状态明确权威修改者，派生缓存明确失效和重建条件。
- 仅外形相似、变化原因不同的代码不强行合并；不为消除少量重复引入更多模式参数和条件分支。公共接口按真实消费者需要保持最小。

## 可信与跨进程边界

- 本项目节点层负责 ComfyUI schema、类型转换与执行入口；普通处理逻辑按真实复杂度拆分。外部供应商协议放在实际调用边界，避免散落在节点 UI 和 schema 中；不预建通用 provider 注册框架。
- 只有当前节点功能明确需要外部 SDK 时才引入，先核验包坐标、版本、导出、运行时、许可与取消/恢复能力。Python 与 JavaScript 的边界按实际契约选择最小方案，不预设常驻服务，也不在浏览器调用 SDK 暴露密钥。
- 若最终需要子进程，明确进程归属、结构化输入输出、错误、超时与取消；不拼接 shell 命令。只有真实长任务与复用需求支持时才引入持久服务，不把当前准备工作变成第二套任务调度系统。

- 按实际运行拓扑确定认证、权威校验、密钥、存储和系统能力的可信执行位置；客户端隐藏或校验不能替代可信侧检查。
- 校验放在真实输入或可信边界；同一可信边界内已由类型、解析或调用契约保证的条件，不逐层重复防御。不同权限、阶段或业务不变量的检查仍须保留，静态类型不能证明外部输入可信。
- 有远端服务时通过明确 API / schema 通信；无远端服务不虚构后端。桌面应用通过具名、受限、可校验的桥接访问宿主能力，不暴露原始 IPC 或通用执行入口。
- 共享契约而非供应商响应或存储内部模型；边界负责转换及错误语义。长任务按需要明确取消、重试、幂等、超时和迟到结果处理。

## 复用与依赖

- 先查现有实现、标准库和已有依赖；复杂成熟能力再比较外部方案与自研成本，按研究规则核验许可、维护、兼容及关键行为。
- 简单局部逻辑优先直接表达或使用具名函数；不为单个简单分支建立注册表、策略框架或通用执行器，不增加无独立职责的透传包装层。
- 抽象应简化当前复杂逻辑、统一真实规则或隔离实际边界；差异确由数据或能力决定时再集中配置或策略。一次使用的辅助函数、单一实现的接口也可有这些价值，不机械按复用次数决定。
- 引入依赖应有当前收益，并计入集成、升级和替换成本；第三方边界的隔离程度与实际风险匹配，不为每个依赖统一套一层。

## 变更边界

- 重构仅在用户要求，或为本次功能实现、根因修复所必需时进行；限于相关代码，不扩展到无关模块。高影响迁移先建立行为基线，迁移消费者后移除旧路径。
- 必要兼容路径明确退出条件，不保留无期限双轨实现。
- 长期且不易从代码推断的决策写入项目既有决策入口；局部细节不另建 ADR，注释解释原因而非复述代码。
- 架构事实变化时同步上下文和受影响规则，不把未经批准的扩展写成既定架构。
