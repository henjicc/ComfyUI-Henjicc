# Git 提交与同步

> 读取时机：开始仓库改动、处理并行工作、提交或同步时。只读分析不执行 pull、rebase 或提交。

## 默认授权

- 仅对既有 Git 仓库执行；不为遵循流程初始化仓库或创建远端。
- 完整改动经匹配验证后主动提交，并普通推送已配置的当前任务上游，无需逐次确认；用户明确禁止时遵循用户要求。
- 该授权不包含其他分支、发布、部署、强制推送、历史改写或修改用户已有提交。

## 现场与同步

1. 修改前检查工作区、当前分支和上游，记录已有改动。安全且存在上游时执行 `git pull --rebase`。
2. 已有改动使 rebase 不安全时，仅对已配置远端 fetch；继续可安全隔离的工作，必要时使用独立 worktree。不得为同步而 stash、覆盖、丢弃或提交他人改动。
3. 完整切片验证通过后及时提交。切换独立目标或开始高风险尝试前，先保存已完成且可验证的成果；不要提交碎片或失败状态。
4. 提交后再次安全执行 `git pull --rebase`，普通推送当前任务上游，并确认 ahead / behind 均为 0。

没有远端、上游、网络或权限时继续能完成的本地工作和提交，不擅自选择推送目标，也不无限重试。分别报告实现、本地提交与远端同步状态，不能把本地完成描述成同步成功。

## 改动归属与提交

- 无论单任务还是并行任务，都只处理本任务改动。并行工作优先使用独立 worktree；共用目录时持续维护精确范围。
- 提交前检查工作区差异，按明确路径或可核对的改动块暂存，再检查 staged diff；禁止 `git add .`、`git commit -a` 和绕过提交钩子。
- 实现与其回归测试属于同一完整切片。不要提交测试失败、契约未闭环、依赖临时调试或混入无关产物的状态。
- 文件内容交织而无法安全拆分时保留现场并说明原因，不覆盖用户工作。
- 提交后确认本任务预期改动已全部提交，已有无关改动保持原样并说明；不以整个工作区干净为由清理已有文件。

## 提交信息与交付

遵循仓库已有规范；没有时使用 `<type>(可选范围): 简洁描述`，如 `docs: 明确初始化状态与规则维护`。标题按项目语言说明最终变化，必要正文解释原因和限制，不复述 diff。

最终报告提交哈希、标题与同步结果；未同步说明原因，存在上游时报告实际一致性检查。未提交的本任务改动及已有无关改动分别说明。非 Git 项目跳过提交，不视为实现失败。
