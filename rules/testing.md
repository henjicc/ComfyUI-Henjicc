# 验证与完成标准

> 读取时机：决定验证范围、验证改动或交付运行结果时。

## 按风险选最小充分证据

| 级别 | 行为变化 | 验证范围 |
|---|---|---|
| L0 | 不改变运行行为的文档、规则、注释 | 格式、路径、引用及指令一致性；不跑无关构建 |
| L1 | 局部低风险逻辑、样式、文案 | 最近的相关测试或静态检查，以及受影响的可见行为 |
| L2 | 公共契约、共享状态、权限、持久化、I/O、并发 | 直接和相关测试、受影响工程检查、对应失败与边界场景 |
| L3 | 影响面无法界定的重构、核心依赖或基础设施变化、发布、用户要求 | 项目约定的全量检查、构建和必要冒烟 / 端到端验证 |

在完整切片首次可验证时执行相关检查；失败先定位，不用更大测试集掩盖。相关验证通过且边界清晰后进入交付，只有新增改动、失败或风险证据才复跑或扩大范围。不要重复执行已被其他命令包含的检查。

## 何时新增测试

- 必要验证不等于每次新增测试。先确认行为变化与现有覆盖缺口；低风险、可逆且已有充分证据的改动，不为完成形式新增测试文件、框架或门禁，仍执行匹配的相关检查。
- 新测试应能指出要防止的具体错误，并在该错误出现时失败；优先覆盖变化的行为、缺陷回归和真实边界，不为测试数量或覆盖率数字堆案例。项目既定门禁仍须满足，不能以精简为由削弱断言或关闭检查。
- 在能可靠发现问题的最小层级补测；不同层级分别验证自身风险，不在单元、集成和端到端层机械复制同一组场景。按有区别的行为和风险选择边界，不穷举无依据的参数组合。

## 证据质量

- 验证用户可观察行为和稳定契约，不镜像实现、堆无意义快照或重复类型系统已保证的事实。不锁定私有字段、内部函数拆分或无契约意义的调用顺序；次数、顺序本身是契约时仍须验证，如只扣款一次。
- 缺陷修复尽量取得稳定失败证据，在合适层补回归测试；验证修复前失败、修复后通过，无法反证时说明替代证据。
- mock 只替代需要隔离的依赖边界，不复刻或绕过被测规则；优先使用简单真实对象或项目已有测试替身，不为方便 mock 给生产代码增加无其他价值的接口、配置或分层。
- 测试数据和辅助函数以让单个用例清楚呈现输入、动作和结果为准；可保留少量直观重复，不为去重建立复杂的 fixture 继承、通用 DSL 或测试专用框架。
- 涉及并发、重试、取消或恢复时，验证迟到结果、重复操作、部分完成和最终权威状态；不要只断言命令成功或事件已发出。
- 新增自动门禁时，在隔离样例或安全可恢复环境构造目标错误，确认检查确实能阻止它。
- 本地检查不等于 CI 已通过；测试、构建产物、运行实例、远端交付分别核验，只执行任务承诺且获授权的层级。

## 规则变更验证

除链接和格式外，按修改涉及的条款及相邻规则走查正常、边界和不应触发的任务，确认没有误触发、停顿或越权。涉及初始化、权限或 Git 流程时，再覆盖受影响的 `pending` / `ready`、状态缺失 / 非法、中断、模板维护、只读、无上游或已有用户改动场景；初始化完成才切换状态，后续更新不会重复初始化。

上述走查是文本逻辑验证，不能宣称已证明模型在实际会话中必然遵循；若需要行为可靠性证据，用隔离项目执行代表性任务，不污染模板状态。

## 节点验证

- 节点测试入口见 [项目上下文](project-context.md)，使用实际宿主 Python 的 unittest 与浏览器联调，不依赖个人工作流，不引入无需求的测试框架。LoadImage 注入行为需覆盖传统画布、Nodes 2.0、设置开关恢复与刷新后图片值保留。
- 节点实现先验证实际计算与输入输出边界，再在正确宿主环境确认注册、安装目标和最小 API 工作流结果；模块名相同不能证明加载的是当前源码。使用宿主 Python，避免只在不含 ComfyUI 的独立环境中通过替身测试。
- 多图/掩码处理覆盖实际支持的 batch、shape、dtype/device 与输入不被原地破坏；工作流契约变化覆盖旧图或提供明确迁移。无相关行为时不机械增加这些测试。
- 外部 API 默认用脱敏 fixture 与网络替身验证转换、失败、取消及重复计费风险；真实模型调用需在现有费用和数据授权内。注册测试与 schema 校验不得触发生成请求。
- 宿主集成前核对队列及用户任务；不能为冒烟中断用户工作、替换同名旧目录或清空全局历史。输出节点用专属测试文件名，结果按自己的 prompt_id 核验，不混用其他任务输出。
- 本包动态输出、连接识别或序列化改变时，用隔离最小图核对前端导出/提交与重开后的有效参数；可用轻量输出验证模式与尺寸，不默认完整采样。模型输入输出及资源适配按 [模型适配验证](model-debugging.md) 取得相应证据，注册、数据流与真实模型执行分别报告。

## UI 验证

按变化选择：文案检查可理解性和受影响布局；交互检查对应键盘、状态和错误路径；共享令牌或组件检查受影响主题、页面和尺寸。使用真实内容及相关极端场景，编译通过不能替代界面结果验证。不要求局部改动遍历无关页面与状态。

- 节点或可见交互改动完成后，在 Codex 右侧内置浏览器打开目标 ComfyUI，展示对应节点或隔离最小验证图。按实际需要刷新前端或重启宿主，确认当前工程源码已生效，检查真实画布与控件，并将视图调整到用户能看清改动的位置；保留展示标签页供用户继续查看。
- 展示不能覆盖用户未保存的工作流或替代执行验证。使用独立临时标签展示对应节点或最小验证图，不依赖个人模板；仅需展示时不额外触发模型生成。纯规则、文档、注释或只改测试且无可见行为变化的任务无需构造演示，用户明确要求演示时照常完成。最终分别说明展示、执行验证与生成结果的实际状态。

## 开发服务

完成由本地开发服务呈现或执行的实现后，按上下文或已核验脚本维护受影响服务：

- 先以工作目录、明确命令、PID / 端口归属确认目标；禁止按 `node`、`python` 等宽泛名称结束进程。
- 未运行时用项目支持的持久方式启动；已运行且必须重启时只重启对应服务；热更新已生效或无需重启时保持原状，不创建第二实例。
- 等待实际就绪信号并核对正式入口；命令返回、进程存在或短暂 ready 日志不等于服务持续可用。
- 纯规则、文档、注释、只改测试且不影响运行环境，或没有长期服务时跳过。涉及真实数据、费用或额外权限时按既有授权边界处理。

最终回复结尾按实际情况选一条：

- `🟢 开发服务已启动`
- `🔄 开发服务已重启`
- `✔️无需重启（开发服务保持运行）`
- `⏭️无需启动（本次改动不影响开发服务）`
- `🔴 开发服务启动失败：<原因>`

## 交付

只报告实际执行的验证及结果。无法验证时说明具体原因、替代证据与剩余步骤，不伪造通过，也不为无关检查未执行而道歉。确认本任务差异、规则同步、必要的迁移 / 生成 / 重启均已处理；Git 提交和同步结果单独按 Git 规则报告。
